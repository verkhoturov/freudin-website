#### Шаг 56. Навигация может потерять несохранённую работу.

**Точки входа:** [`src/views/settings`](../../src/views/settings), [`src/widgets/profile-form`](../../src/widgets/profile-form), [`src/shared/lib/use-unsaved-changes-warning.ts`](../../src/shared/lib/use-unsaved-changes-warning.ts).

Сценарий: психолог пишет длинный ответ FAQ и меняет раздел настроек. Форма пересоздаётся;
переход по ссылке предлагает отказаться от правок или остаться, а «Назад» браузера не защищён.
- [ ] <a id="step-56-1"></a>**56.1. 🤖 ИИ:** сохранять черновики разделов при навигации внутри настроек, включая
      «Назад» и «Вперёд», без записи в профиль до Save. После успешного сохранения обновлять
      исходные значения черновика; при ошибке сохранять введённое.
- [ ] <a id="step-56-2"></a>**56.2. 🤖 ИИ:** для перехода с несохранёнными правками предложить Save and continue,
      Discard changes и Stay. Не продолжать переход, если сохранение завершилось ошибкой.
      Сохранить предупреждение при закрытии и перезагрузке вкладки. Если черновик будет
      храниться в браузерном хранилище, обновить `/privacy`, `/terms` и дату Last updated.
- [ ] <a id="step-56-3"></a>**56.3. 🧑‍💻 Разработчик:** проверить переходы между разделами, историю браузера,
      отмену перехода и ошибку сохранения на компьютере и телефоне.
- [ ] <a id="step-56-4"></a>**56.4. 🤖 ИИ:** при ошибке в скрытом разделе называть раздел и поле, дать перейти к ошибке
      с сохранением черновика и фокусом. Проверить связку City / In person и ссылки
      Change it in Account; выбранную галочку общий CheckboxGroup уже позволяет снять.

**Готово, когда:** навигация не уничтожает введённое без явного отказа пользователя,
а неудачное сохранение не уводит его из формы.

**Точки входа:** [`src/widgets/profile-form/ui/appearance-block.tsx`](../../src/widgets/profile-form/ui/appearance-block.tsx), [`src/widgets/profile-form/ui/profile-form.tsx`](../../src/widgets/profile-form/ui/profile-form.tsx).

а выбор пользователя о сворачивании сохраняется.

<a id="step-60"></a>

#### Шаг 60. Превью слабо помогает редактировать нижние блоки.

**Точки входа:** [`src/widgets/profile-form/ui/profile-form.tsx`](../../src/widgets/profile-form/ui/profile-form.tsx), [`src/views/settings/ui/settings-view.tsx`](../../src/views/settings/ui/settings-view.tsx).

При редактировании FAQ или контактов форма показывает нужные поля, но превью остаётся
на фото и биографии. Соответствующий блок приходится искать отдельной прокруткой.
- [ ] <a id="step-60-1"></a>**60.1. 🤖 ИИ:** при явном выборе блока редактора переходить к соответствующему
      блоку превью. Не прокручивать превью при каждом вводимом символе; для пустого блока,
      которого ещё нет на странице, не создавать неожиданных скачков.
- [ ] <a id="step-60-2"></a>**60.2. 🤖 ИИ:** проверить нижние блоки, изменённый порядок, свёрнутые блоки и переход
      из Edit в Preview на телефоне. Фокус ввода должен оставаться в редактируемом поле.
- [ ] <a id="step-60-3"></a>**60.3. 🧑‍💻 Разработчик:** проверить редактирование FAQ и контактов с длинной страницей.
- [ ] <a id="step-60-4"></a>**60.4. 🤖 ИИ:** сохранять положение формы и превью раздельно при Preview ↔ Edit на телефоне.
      Возвращать пользователя к редактируемому FAQ/Contacts, включая изменённый порядок
      блоков и раскрытие ошибки; не отправлять его без необходимости в начало формы.

**Готово, когда:** пользователь быстро видит результат правки выбранного блока и может
продолжать писать без скачков прокрутки и потери фокуса. Возврат из Preview в Edit сохраняет место редактирования.

#### Шаг 61. Search details перегружен и обещает результат раньше времени.

**Точки входа:** [`src/widgets/profile-form/ui/practice-selects.tsx`](../../src/widgets/profile-form/ui/practice-selects.tsx), [`src/entities/profile/config/concerns.ts`](../../src/entities/profile/config/concerns.ts), [`src/views/settings`](../../src/views/settings).

Выполненные подшаги и результаты проверок — в [истории](../plan/HISTORY.md#step-61).

При работе с несколькими категориями клиентов доступны 77 запросов в 11 группах; на телефоне
раздел занимает около 3243 px. Превью публичной страницы не отражает эти закрытые данные,
а текст Used to match you with clients обещает уже работающий подбор.
- [ ] <a id="step-61-1"></a>**61.1. 🤖 ИИ:** убрать превью из Search details и использовать освободившееся место
      для формы. Сохранить отделение закрытых данных от публичного профиля.
- [ ] <a id="step-61-2"></a>**61.2. 🤖 ИИ:** сделать группы запросов сворачиваемыми, показывать количество
      выбранного и сводку выбранных запросов. Сохранить зависимость доступных групп от
      Works with и правила отбрасывания недоступных запросов.
- [ ] <a id="step-61-4"></a>**61.4. 🧑‍💻 Разработчик:** проверить выбор, повторное открытие и сохранение запросов
      при разных Works with, на компьютере и телефоне.
- [ ] <a id="step-61-5"></a>**61.5. 🤖 ИИ:** добавить поиск по доступным запросам и просмотр выбранных, сохранив выбор
      при фильтрации. Явно объяснить приватность раздела; формулировки чувствительных
      запросов проверить с профессиональной аудиторией без обещаний диагностики/подбора.

**Готово, когда:** выбранное легко проверить, закрытые данные не попадают в превью,
а описание соответствует реально работающим возможностям.

<a id="step-62"></a>

#### Шаг 62. Практические условия работы появляются слишком поздно.

**Точки входа:** [`src/widgets/profile-card/ui/practice-details.tsx`](../../src/widgets/profile-card/ui/practice-details.tsx), [`src/widgets/profile-card/ui/profile-card.tsx`](../../src/widgets/profile-card/ui/profile-card.tsx).

В проверенном профиле на телефоне 320 px Format начинается примерно на 757 px, Price —
на 949 px. До них посетитель читает стаж и подробный список подходов.
- [ ] <a id="step-62-1"></a>**62.1. 🤖 ИИ и 🧑‍💻 Разработчик:** согласовать компактную сводку после короткой Bio:
      формат работы, языки, место и стоимость; учитывать цены услуг, если общей цены нет.
- [ ] <a id="step-62-2"></a>**62.2. 🤖 ИИ:** реализовать согласованную иерархию и исходный порядок блоков для
      новых страниц. Сохранить выбранный владельцами порядок существующих страниц,
      не дублировать одинаковые сведения и не показывать пустые значения.
- [ ] <a id="step-62-3"></a>**62.3. 🧑‍💻 Разработчик:** проверить, что условия работы легко найти на телефоне,
      в том числе у онлайн-профиля и профиля с несколькими ценами услуг.

**Готово, когда:** посетитель быстро узнаёт формат, язык, место и стоимость работы,
а настройки существующей страницы не меняются без решения владельца.

<a id="step-63"></a>

#### Шаг 63. Действия владельца спрятаны внизу страницы.

**Точки входа:** [`src/widgets/profile-card/ui/profile-card.tsx`](../../src/widgets/profile-card/ui/profile-card.tsx).

У полностью заполненной страницы Edit и Share стоят после всех блоков. Для редактирования
приходится искать Settings в меню или прокручивать страницу до конца.
- [ ] <a id="step-63-1"></a>**63.1. 🤖 ИИ:** разместить компактную панель Edit page / Share рядом с именем
      владельца. Посетитель не должен видеть элементы управления владельца; превью
      редактора остаётся без них. Сохранить доступное посетителю действие Share.
- [ ] <a id="step-63-2"></a>**63.2. 🧑‍💻 Разработчик:** проверить свою и чужую страницу, просмотр гостем
      и превью на компьютере и телефоне.

**Готово, когда:** владелец может редактировать страницу и поделиться ей с первого экрана,
а служебные действия не мешают посетителю.

<a id="step-64"></a>

#### Шаг 64. Чек-лист неправильно оценивает заполненные цены.

**Точки входа:** [`src/widgets/profile-card/ui/owner-checklist.tsx`](../../src/widgets/profile-card/ui/owner-checklist.tsx), [`src/shared/config/routes.ts`](../../src/shared/config/routes.ts).

**Связи:** Одна реализация с приёмкой в [70](stage-o.md#step-70).

Выполненные подшаги и результаты проверок — в [истории](../plan/HISTORY.md#step-64).

Сценарий: формат работы выбран, услуги содержат цены и длительность, но общая цена профиля
не задана. Пункт Add your work format and price продолжает считать страницу незавершённой.
- [ ] <a id="step-64-4"></a>**64.4. 🤖 ИИ:** вести Add a photo к полю фото с фокусом, а Add your work format and price —
      к действительно недостающей части: формату, общей цене либо Services. Проверить
      раскрытие блока, сохранение черновика и сценарии с ценами услуг; связать с шагом 70.

**Готово, когда:** чек-лист признаёт заполненные условия работы и не просит добавить
искусственную общую цену. То же исправление закрывает шаг 70 этапа O.
