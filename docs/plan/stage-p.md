Доработки по двум отчётам Lighthouse 13.4.1 от 12.10.2026: личная страница `/<username>`
и редактор `/settings`. Этап охватывает только **Performance** и **Accessibility**.
15.10.2026 выполнен 79.2; остальные пункты 72–80 впереди. Общие исправления изображений выполняются один раз
и проверяются на обеих страницах.

Исходные результаты — одиночные мобильные прогоны с симуляцией сети и замедлением CPU ×4.
В них присутствовало расширение React DevTools, поэтому перед оптимизацией нужен чистый замер.

| Страница | Performance | Accessibility | LCP | TBT | CLS |
|----------|------------:|--------------:|----:|----:|----:|
| Личная страница из отчёта | 90 | 100 | 3.55 с | 0 мс | 0 |
| `/settings` | 84 | 94 | 4.30 с | 112 мс | 0 |

Цель: Performance личной страницы — **100 в сопоставимых контрольных прогонах**,
Performance настроек — **90+**, Accessibility обеих страниц — **100**. Итог подтверждается
замерами после реализации. Для текущего отчёта личной страницы расчёт при неизменных
остальных метриках даёт примерно 97 баллов при LCP 2.5 с, 99 при 2 с и 100 при 1.5 с;
это ориентир, а не уже полученный результат.

#### Шаг 73. Аватар загружается сразу и с высоким приоритетом

**Точки входа:** [`src/entities/profile/ui/profile-avatar.tsx`](../../src/entities/profile/ui/profile-avatar.tsx), [`src/views/profile/ui/profile-page.server.tsx`](../../src/views/profile/ui/profile-page.server.tsx).

**Связи:** Замеры сравниваются с исходной точкой [72](stage-p.md#step-72).

В обоих отчётах LCP — аватар размером 96×96 CSS px. В Classic и Banner компонент
`ProfileAvatar` использует Radix Avatar: изображение отсутствует в первоначальном HTML,
а внутренний `new Image()` начинает загрузку после запуска JavaScript. Адрес фото публичной
страницы уже известен серверу. Простого `fetchPriority` на итоговом `<img>` недостаточно.
- [ ] <a id="step-73-1"></a>**73.1. 🤖 ИИ:** изменить загрузку в `entities/profile/ui/profile-avatar.tsx`, чтобы
      фото личной страницы присутствовало в серверном HTML и браузер находил его сразу.
      Сохранить инициалы при отсутствии фото, обработку ошибки изображения, `alt`, размеры
      и `referrerPolicy`; проверить Classic, Banner и Hero в `widgets/profile-card/ui/page-cover.tsx`.
- [ ] <a id="step-73-2"></a>**73.2. 🤖 ИИ:** задать высокий приоритет именно первоначальному запросу основного
      фото первого экрана. В `/settings` начать его загрузку сразу после получения адреса
      из `/api/me`; сохранить клиентскую загрузку данных настроек. Маленькие аватары меню
      и второстепенные изображения не должны конкурировать с основным фото.
- [ ] <a id="step-73-3"></a>**73.3. 🤖 ИИ и 🧑‍💻 Разработчик:** проверить waterfall: фото публичной страницы
      запрашивается до гидратации, фото настроек — сразу после получения данных;
      в начале загрузки приоритет высокий, нет повторных загрузок и новых сдвигов макета.

**Готово, когда:** аватар публичной страницы не ждёт JavaScript, в настройках отсутствует
дополнительное ожидание после `/api/me`, fallback и доступное имя изображения сохранены.

В нём присутствуют Zod и схемы профиля. В настройках часть того же чанка нужна форме;

- [ ] <a id="step-77-1"></a>**77.1. 🤖 ИИ:** установить цепочку импортов и состав чанка в производственной
      сборке: `views/profile`, `widgets/profile-card`, public API сущностей и сценарий
      скрытой страницы с паролем. Отделить код отображения от схем редактирования
      и частей, используемых только при открытии соответствующего сценария.
- [ ] <a id="step-77-2"></a>**77.2. 🤖 ИИ:** убрать подтверждённо лишний код из начальной загрузки публичной
      страницы через существующие public API и отложенные импорты. Сохранить валидацию
      форм, доступ по паролю, контакты, Share и обновление кеша после сохранения настроек.
- [ ] <a id="step-77-3"></a>**77.3. 🤖 ИИ:** сравнить реальные скачанные байты и LCP для обеих страниц;

      «unused JavaScript» автоматически удаляемым кодом.

**Готово, когда:** публичная страница скачивает меньше ненужного для первого экрана JS,
связанные сценарии работают, валидация настроек и закрытых страниц сохранена.
