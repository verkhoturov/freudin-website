# Общая QA шагов 83 → 82 → 94 → 96

Реализация 16–17.10.2026, итоговая QA 17.10.2026: **PASS**.
Критерии и результаты — [основной отчёт QA-агента](qa-report.md), отдельное уточнение
успешного Save перед выходом — [дополнительный отчёт](qa-account-leave.md).

## Изменения

- **83:** View my page доступен в навигации каждого раздела настроек и использует сохранённый
  username. Save and continue после переименования ведёт на новый адрес; Stay и Discard
  используют существующую защиту черновика.
- **82:** загрузка и удаление документов обозначены как немедленные операции, которые Discard
  не отменяет; Highlight и порядок блоков требуют Save. Действия аккаунта отделены от формы.
  Выход и переход к провайдеру сначала проходят Save / Discard / Stay. Переход после успешного
  Save ожидает `mutateAsync`, поэтому переживает пересоздание формы.
- **94:** только подтверждённый владелец получает имя профиля в заголовке вкладки. При уходе
  прежний title восстанавливается, если Next.js ещё не установил новый. Серверные metadata
  закрытой страницы без доступа остаются нейтральными.
- **96:** ответы FAQ остаются в исходном HTML через `forceMount`; управляемый аккордеон
  задаёт `hidden` закрытому content. Связи trigger/content явные, длинный текст не ограничен
  измеренной высотой внутренней обёртки.

## Среда и проверки

Production-сборка Next.js 16.3.6, [build ID и SHA-256 исходников](source.json).
`localhost:3100` проксировал UI на Next.js `:3002`. Все API и Supabase-запросы завершались
во временном локальном fixture-server; процесс Next.js использовал локальный `SUPABASE_URL`
и вымышленные ключи. Неизвестные API-запросы блокировались. Профиль Anna Example, документы
и сессия владельца вымышлены; записи в production отсутствовали.

- `npm run check`: Biome и TypeScript без ошибок, **144 теста в 15 файлах** прошли.
- `npm run build`: PASS; финальная сборка использовалась в обоих завершённых прогонах QA.
- QA-агент `opencode/gpt-6-luna` через `agent-browser`: 1280×900, 390×844 и контроль 320×800,
  светлая и тёмная темы. Проверены переходы между разделами, переименование, Stay/Discard,
  загрузка/удаление и ошибки документов, Save перед действиями аккаунта, private/password
  владельца и гостя, задержка/ошибка `/api/me`, FAQ и превью с ответом длиной 1000 символов.
- [Проверка исходного HTML FAQ](ssr-demo.json): оба ответа находятся вне script/style,
  оба content скрыты, `aria-controls` и `aria-labelledby` связаны даже в закрытом состоянии.
- [Проверка HTML закрытых страниц](ssr-private.json): нейтральные title и `noindex`,
  имя владельца отсутствует во всём исходном HTML, включая скрипты.
- [Уточнение результата выхода](account-leave.json): после точного ожидания pathname `/`
  Bio сохранён, `owner=false`, ровно один PATCH профиля, затем один POST выхода, диалога нет.
- Скриншоты просмотрены основным агентом; неожиданных render/hydration ошибок не обнаружено.
  Гостевые 401 и намеренно включённые 500 стенда отделены от ошибок приложения.

Первый запуск на промежуточной сборке прервался без итогового отчёта и не засчитывался.
В завершённом основном прогоне измерение E1 с `wait --url` сначала совпало с префиксом
`/settings`; дополнительный прогон дождался точного pathname и подтвердил результат.
Полные логи, brief и изображения остаются локально в `tmp/qa-83-82-94-96-final/` и
`tmp/qa-83-82-94-96-verify/`; они не включены в репозиторий.

## Границы доказательств

Это проверка интерфейса и production-рендера на изолированном локальном стенде. Реальные
Supabase/RLS/Storage, провайдеры входа, опубликованный production и физические устройства
не проверялись. Подтверждение удаления аккаунта запрещалось и не выполнялось.
Частичный сбой фото 65.4, стабильная база и конфликты 66, ввод во время Save 81 остаются
отдельными открытыми задачами.

Новые автотесты не добавлялись. При отдельном запросе кандидаты для автоматизации:
`src/widgets/profile-form/ui/profile-form.test.tsx` — новое имя после Save, остановка действия
при ошибке и выход после пересоздания формы; `src/widgets/profile-card/ui/faq-list.test.tsx` —
HTML закрытых ответов, скрытие и клавиатура. Для таких UI-тестов нужно отдельно согласовать
DOM-окружение: существующий Vitest работает в `node`.
