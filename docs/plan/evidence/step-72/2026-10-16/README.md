## Условия

- Lighthouse **13.4.1**, Chromium **Chrome/155.0.8059.79**, Next.js **16.3.6**, Node.js 24.14.1.
- Commit `d2ae85fcdb2000ee2928a1c6090c9ce489cb3249`, поверх него есть незакоммиченные изменения исходников; их SHA-256 `0c66cba8bb7bedf16102cc4f4cd8d7d009bb8a746cf461656e3976ec56604682`. Build ID `FE5htaZLXWGx4C4JoQdUX`. Фактические исходники не менялись между прогонами.
- Viewport **412×823**, DPR **1.75**, mobile, светлая тема. Во всех шести JSON есть числовое свидетельство размеров в `auditViewport` на DOMContentLoaded. `observedAfterAudit` относится к состоянию после завершения Lighthouse: оно уже может иметь восстановленную ширину 1280 px.
- Симуляция Slow 4G: RTT **150 мс**, throughput **1638.4 Kbps**, CPU slowdown **×4**; полные параметры — в `method.json`. Это настройки модели Lighthouse, не характеристики реального телефона или соединения.
- Отдельные временные Chromium-сессии с `--disable-extensions`, без extension targets/запросов и без React DevTools hook. Публичная страница — гость, `/settings` — вошедший владелец, раздел Public profile, Appearance свёрнут. Один и тот же профиль, фото и документ во всей серии.
- Перед каждой навигацией: about:blank, очистка браузерного HTTP-кеша через `Network.clearBrowserCache`, CacheStorage/ServiceWorker/shader cache через `Storage.clearDataForOrigin`; cookies и localStorage сохранены. Это холодный **кеш браузерных ресурсов**; DNS/соединения, кеши Supabase/CDN и серверные кеши не объявляются холодными. Production-сервер прогрет подготовкой; dev3000/Storybook6006 оставлены без активного QA. Прочие приложения пользователя не контролировались.
- Порядок: public1 → settings1 → public2 → settings2 → public3 → settings3. Более ранние подготовительные серии с неполной фиксацией viewport в эту выборку не входят; все шесть опубликованных файлов получены одной финальной серией с одинаковой инструментальной проверкой размера.
- Источники методики: [авторизованные страницы](https://github.com/GoogleChrome/lighthouse/blob/main/docs/authenticated-pages.md), [throttling](https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md). Использован Node API на подготовленной странице; сохранение сессии дополнено явной очисткой ресурсного кеша.

## Доступность и диагностические элементы

Во всех шести прогонах Accessibility 100, ошибочных автоматических accessibility-проверок и их узлов нет; runtimeError, auditError и warnings отсутствуют. Это результат автоматического Lighthouse, а не полная проверка скринридером или на физических устройствах.

Performance фиксирует проблемы доставки изображений. Конкретные селекторы из JSON:

- Публичная страница: `div.mx-auto > article.mx-auto > span.group/avatar > img.aspect-square` — `lcp-discovery-insight` и `image-delivery-insight`; `ul.flex > li > button.flex > img.h-24` — `image-delivery-insight`.
- Настройки: `fieldset#photo > div.flex > span.group/avatar > img.aspect-square` и `div.flex > ul.flex > li.flex > img.size-16` — `image-delivery-insight`.

На публичной странице два CLS 0,00036651 и один 0; медиана не округлена до нуля. В настройках все три CLS равны 0. Цели этапа P по Performance ещё не достигнуты; следующая работа — 73–75 и дальнейшая приёмка 79.3/80, не реализация в шаге 72.

В измерительной серии `/api/me` возвращал 401 для гостя и 200 для владельца; HTTP 500 не было. Профиль и закрытые данные до/после совпали, записи не выполнялись. Ранее, в отдельном UI QA, был единичный 500 с последующим 200; локальный сервер записал `PGRST303: JWT issued at future`. Этот ответ не входит в финальную измерительную серию и не относится к исправлению aria-label.
