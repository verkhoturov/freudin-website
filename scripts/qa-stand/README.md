# Стенд приёмки для QA-агента

Локальный сервис, на котором QA-агент проверяет интерфейс без боевой базы. Обычный
`localhost:3000` работает с production Supabase и под настоящим аккаунтом. Поэтому часть
состояний там недоступна, а часть проверок меняет реальные данные:

- гость и владелец одной страницы, скрытая страница и страница с паролем;
- задержка и ошибка 500 у `/api/me`, ошибки сохранения и загрузки документов;
- Save без записи в боевую базу;
- серверный HTML production-сборки, а не dev-сервера.

На стенде всё это включается одним запросом к пульту. Данные вымышленные: профиль Anna Example,
страница `qa-anna`.

## Как устроен

`npm run qa:stand` запускает `next start` на `:3002` с вымышленными ключами и сервер стенда
на `:3100`. Браузер открывает `:3100`. Страницы стенд проксирует в Next.js, а запросы к нашему
`/api/*` и к Supabase обрабатывает сам. Остальные запросы к API и Supabase он блокирует.
Настоящие значения из `.env` в процесс Next.js не попадают.

Данные и ответы стенда описаны типами из `src`. Если API или схема базы изменятся, а стенд нет,
`npm run check` покажет ошибку.

## Чего стенд не проверяет

Наш API, RLS, Storage и вход через провайдеров здесь подменены. Стенд проверяет только интерфейс
и серверный рендер, а работу с данными — тесты и проверка на `localhost:3000`. Оптимизация фото
через `next/image` здесь тоже не проверяется: Next.js 16 не берёт картинки с локальных адресов.

Если стенду нечем ответить на запрос, он возвращает 403 и пишет `"blocked": true` в
`tmp/qa-stand/requests.jsonl`. Это пробел стенда, а не ошибка приложения: стенд нужно дополнить.
